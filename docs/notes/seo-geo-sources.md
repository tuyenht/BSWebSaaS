## A. Crawling and indexing speed
A1. Eligibility for AI features = being indexed. "To be eligible to be shown as a supporting link in AI Overviews or AI Mode, a page must be indexed" / "There are no additional technical requirements." https://developers.google.com/search/docs/appearance/ai-features
A2. Discovery by links. "Google primarily finds pages through links from other pages it already crawled." https://developers.google.com/search/docs/fundamentals/seo-starter-guide
A3. Sitemap lastmod. "Google uses the <lastmod> value if it's consistently and verifiably" accurate; should reflect "the last significant update to the page". "Google ignores <priority> and <changefreq> values." Limit 50MB uncompressed or 50,000 URLs per file (use a sitemap index). https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap
A4. Google sitemap ping is gone: unauthenticated ping endpoint deprecated June 2023, now returns 404; submit via robots.txt "Sitemap:" line or Search Console. https://developers.google.com/search/blog/2023/06/sitemaps-lastmod-ping (via search summary, page not opened directly: chưa kiểm verbatim)
A5. HTTP caching. "Google's crawling infrastructure supports ETag and If-None-Match as defined by the HTTP Caching standard." Same for Last-Modified / If-Modified-Since; if both sent, ETag is used; ETag preferred. https://developers.google.com/search/docs/crawling-indexing/overview-google-crawlers#http-caching
A6. Crawl budget (advanced guide, aimed at 1M+ pages weekly or 10,000+ pages daily): "Support 304 (Not Modified) HTTP status codes."; "soft 404 pages will continue to be crawled, and waste your budget."; "we recommend including the <lastmod> tag."; consolidate or robots-block duplicate sorted/filter variants. https://developers.google.com/search/docs/crawling-indexing/large-site-managing-crawl-budget
A7. Image sitemap: image:loc required ("The URL of the image."); caption, geo_location, title, license tags removed from docs. https://developers.google.com/search/docs/crawling-indexing/sitemaps/image-sitemaps
A8. IndexNow protocol: host a UTF-8 key file "{your-key}.txt" at site root (or keyLocation param); GET https://<searchengine>/indexnow?url=...&key=...; batch POST /indexnow JSON {host,key,urlList}, up to 10,000 URLs; engines adopting it "agree that submitted URLs will be automatically shared with all other participating search engines". https://www.indexnow.org/documentation . The page does not say whether Google participates; searchengines page did not list engines (data is in searchengines.json: chưa kiểm). Authors named: Internet Archive, Seznam, Yandex, Microsoft. https://www.indexnow.org/searchengines
A9. Bing: lastmod "remains a key signal, helping Bing prioritize URLs for recrawling"; "changefreq and priority are ignored by Bing"; "Combining sitemaps for comprehensive site coverage with IndexNow for fast, URL-level submission." https://blogs.bing.com/webmaster/2025/7/Keeping-Content-Discoverable-with-Sitemaps-in-AI-Powered-Search/
A10. Bing ties IndexNow to AI freshness: "IndexNow notifies participating search engines when URLs are added, updated, or deleted." https://blogs.bing.com/webmaster/December-2025/Does-Duplicate-Content-Hurt-SEO-and-AI-Search-Visibility ; AI Performance report in Bing Webmaster Tools (Feb 2026 post): https://blogs.bing.com/webmaster/February-2026/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview (help page itself returned no text: chưa kiểm)
A11. Cốc Cốc: no primary source found for IndexNow support or webmaster tools ("not found"). Search returned only Bing, Yandex, Naver as IndexNow supporters (secondary).

## B. Page structure and HTML
B1. Titles: "a good title is unique to the page, clear and concise, and accurately describes the contents of the page." Descriptions: "short, unique to one particular page". Descriptive words in URLs; clear anchor text; sharp images placed near relevant text. https://developers.google.com/search/docs/fundamentals/seo-starter-guide
B2. Links must be crawlable: "Google can only discover your links if they are <a> HTML elements with an href attribute." https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics
B3. SSR: "server-side or pre-rendering is still a great idea" and "not all bots can run JavaScript." Real status codes matter ("All pages with a 200 HTTP status code are sent to the rendering queue"). Same URL. Our Blade SSR fits.
B4. Robots meta: nosnippet "Do not show a text snippet or video preview in the search results for this page."; max-snippet "Use a maximum of [number] characters as a textual snippet"; data-nosnippet marks textual parts not to be used; max-image-preview sets image preview size; noindex. https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag . Google's updates log: AI Mode info added to robots meta docs 5 Mar 2025. https://developers.google.com/search/updates
B5. Restrictive controls reduce AI use: "More restrictive permissions will limit how your content is featured in our AI experiences." (nosnippet, data-nosnippet, max-snippet, noindex). https://developers.google.com/search/blog/2025/05/succeeding-in-ai-search
B6. Duplicate content (Bing): "Apply canonical tags when multiple versions must remain accessible." "each page has a clear purpose and adds distinct value". https://blogs.bing.com/webmaster/December-2025/Does-Duplicate-Content-Hurt-SEO-and-AI-Search-Visibility

## C. Structured data
C1. General: "JSON-LD (recommended)"; "Don't mark up content that is not visible to readers of the page."; "Your structured data must be a true representation of the page content." https://developers.google.com/search/docs/appearance/structured-data/sd-policies
C2. Organization: put on home page or one About page, not every page. Recommended: name, url, logo (min 112x112, crawlable), sameAs, address. https://developers.google.com/search/docs/appearance/structured-data/organization
C3. Article: no required props. headline ("concise"), image (relevant, not logos), datePublished, dateModified (with timezone). "Make sure that all the authors that are presented as authors on the web page are also included in markup." Author: only name, Person or Organization. Types Article/NewsArticle/BlogPosting. https://developers.google.com/search/docs/appearance/structured-data/article
C4. Product snippet: only required property is name; but "Product snippets require either review or aggregateRating or offers" (one of three). Only pages focused on a single product. Past priceValidUntil may suppress the snippet. https://developers.google.com/search/docs/appearance/structured-data/product-snippet . Consequence for catalogues without prices: no Product rich result from Google is available without review/aggregateRating/offers; the markup is still valid schema.org and can help understanding (C9), but do not invent offers or ratings (C1).
C5. Merchant listing: "merchant listings require an Offer as the merchant has to be the seller of the product"; "require a price greater than zero." So not applicable to price-less catalogues. https://developers.google.com/search/docs/appearance/structured-data/merchant-listing
C6. BreadcrumbList: itemListElement with ListItem position, name, item; at least two items; "represent a typical user path to a page, instead of mirroring the URL structure." https://developers.google.com/search/docs/appearance/structured-data/breadcrumb
C7. LocalBusiness: required address, name; recommended geo, openingHoursSpecification, telephone, url; "Use the most specific LocalBusiness sub-type possible". https://developers.google.com/search/docs/appearance/structured-data/local-business
C8. FAQ: Google updates log 8 May 2026: "This feature will no longer appear in Google Search starting May 7, 2026."; 15 Jun 2026: "The FAQ rich result feature is no longer shown in Google Search results". FAQ docs removed. So FAQPage markup has no Google rich-result value now; visible FAQ content is still fine as content. https://developers.google.com/search/updates ; https://developers.google.com/search/docs/appearance/structured-data/faqpage . Other deprecations: special announcements (31 Jul 2025), practice problem + dataset (Nov 2025 to Jan 2026). Not read: whether Bing still uses FAQPage (chưa kiểm).
C9. ItemList carousel (Google): only with Course, Movie, Recipe, Restaurant; at least two ListItem; same type; summary-page URLs on same domain. https://developers.google.com/search/docs/appearance/structured-data/carousel . So ItemList on a product category page gives no Google carousel; usable as plain schema.org only.
C10. schema.org Product props for price-less catalogues, all present on the type page, none required: manufacturer ("The manufacturer of the product."), material, category, additionalProperty ("A property-value pair representing an additional characteristic of the entity"), brand, sku, mpn, gtin, isRelatedTo. offers is optional. https://schema.org/Product
C11. CollectionPage: "Web page type: Collection page." mainEntity: "Indicates the primary entity described in some page or other CreativeWork." https://schema.org/CollectionPage . Service: "A service provided by an organization"; provider, serviceType, areaServed, offers, category. https://schema.org/Service
C12. @id: in JSON-LD the identifier is "@id" (schema.org datamodel). That page gives no graph-linking guidance; @graph with shared @id (Organization referenced from WebSite/Article publisher) is a JSON-LD practice, no schema.org or Google primary quote found: chưa kiểm. https://schema.org/docs/datamodel.html
C13. No special markup for AI: "Structured data isn't required for generative AI search, and there's no special schema.org markup you need to add." https://developers.google.com/search/docs/fundamentals/ai-optimization-guide

## D. Titles, descriptions, content quality
D1. Title links: auto-generated from several sources; "Avoid repeated or boilerplate text in <title> elements."; keep brand short at start or end; Google may rewrite titles. https://developers.google.com/search/docs/appearance/title-link
D2. Snippets: "Snippets are automatically created from page content."; meta description used when more accurate; unique per page, site-level for home and listing pages; "Identical or similar descriptions on every page of a site aren't helpful."; avoid keyword lists. Page does not call description a ranking factor. https://developers.google.com/search/docs/appearance/snippet
D3. People-first: "People-first content means content that's created primarily for people, and not to manipulate search engine rankings."; E-E-A-T "trust is most important"; Who (bylines), How, Why. https://developers.google.com/search/docs/fundamentals/creating-helpful-content
D4. For AI search: "Focus on making unique, non-commodity content that visitors from Search and your own readers will find helpful"; good page experience; keep Merchant Center and Business Profile data current; support text with quality images and video. https://developers.google.com/search/blog/2025/05/succeeding-in-ai-search
D5. Bing AI Performance help says content quality, structure, freshness help but guarantee no citation (via search summary: chưa kiểm verbatim).

## E. GEO / AI search
E1. Google: "There are no additional requirements to appear in AI Overviews or AI Mode, nor other special optimizations necessary." "You don't need to create new machine readable files, AI text files, or markup to appear in these features." https://developers.google.com/search/docs/appearance/ai-features
E2. Google AI optimization guide (published 15 May 2026): "optimizing for generative AI search is optimizing for the search experience, and thus still SEO."; "There's no requirement to break your content into tiny pieces for AI to better understand it."; section "Mythbusting generative AI search: what you don't need to do"; query fan-out = "A set of concurrent, related queries generated by the model to request more information". Search summary says a 15 Jun 2026 update added that llms.txt is ignored by Google Search, neither helps nor harms (not seen verbatim on the page I fetched: chưa kiểm). https://developers.google.com/search/docs/fundamentals/ai-optimization-guide ; https://developers.google.com/search/blog/2026/05/a-new-resource-for-optimizing (not opened). Search Console has a Generative AI performance report (search summary, chưa kiểm).
E3. Google-Extended: "does not impact a site's inclusion in Google Search nor is it used as a ranking signal in Google Search"; controls Gemini training and grounding in Gemini Apps / Vertex. Blocking it does not remove you from AI Overviews (page does not mention AI Overviews; the control for Search is Googlebot robots.txt plus nosnippet family per E1). https://developers.google.com/search/docs/crawling-indexing/google-common-crawlers
E4. OpenAI: OAI-SearchBot "is used to surface websites in search results in ChatGPT's search features."; opt-out sites "will not be shown in ChatGPT search answers, though can still appear as navigational links."; GPTBot = training crawler; ChatGPT-User = user actions, "not used to determine whether content may appear in Search". Allow OAI-SearchBot in robots.txt; changes take about 24 h. https://developers.openai.com/api/docs/bots
E5. Perplexity: PerplexityBot "is designed to surface and link websites in search results on Perplexity", "not used to crawl content for AI foundation models"; Perplexity-User "generally ignores robots.txt rules" because a user requested the fetch. https://docs.perplexity.ai/guides/bots
E6. Anthropic: ClaudeBot = training crawler; Claude-User = user requests; Claude-SearchBot "navigates the web to improve search result quality for users"; blocking it "may reduce visibility in Claude's search results"; supports non-standard Crawl-delay; IP blocking not a reliable opt-out. https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler
E7. Bing Copilot: no dedicated ranking guidance found beyond sitemap+lastmod+IndexNow, canonicals, clear intent ("Clearer intent strengthens AI visibility by helping models understand which version to trust and surface."), and the AI Performance report. Bing webmaster guidelines page returned no text: chưa kiểm.
E8. llms.txt proposal: "a proposal to standardise on using an /llms.txt file to provide information to help agents use a website"; Markdown; only required part an H1. https://llmstxt.org/ . Google: ignored (E1, E2). Gary Illyes / John Mueller statements only via secondary coverage (searchengineland.com/google-says-normal-seo-works-for-ranking-in-ai-overviews-and-llms-txt-wont-be-used-459422): not primary.
E9. GEO paper (Aggarwal et al.): "Through rigorous evaluation, we demonstrate that GEO can boost visibility by up to 40% in generative engine responses." Results (arxiv HTML): Quotation Addition 27.8 vs baseline 19.5 on position-adjusted word count; Statistics Addition 25.9; Cite Sources 24.9 (top three "a relative improvement of 30-40%"); Keyword Stuffing 17.8, below baseline, "10% worse than the baseline" on Perplexity.ai; Cite Sources gave "a substantial 115.1% increase in visibility for websites ranked fifth in SERP" while the top site fell 30.3%. https://arxiv.org/abs/2311.09735 ; https://arxiv.org/html/2311.09735 . Limit: 2023 study, simulated engines + Perplexity, effect varies by domain; not Google's production systems.

## F. Performance
F1. Core Web Vitals good thresholds: LCP "within the first 2.5 seconds"; INP "less than 200 milliseconds"; CLS "less than 0.1"; "aligns with what our core ranking systems seek to reward." INP replaced FID on 12 Mar 2024. https://developers.google.com/search/docs/appearance/core-web-vitals ; https://developers.google.com/search/updates
F2. Page latency/page experience named as a recommendation for AI search too (D4).
F3. 304 + ETag reduce crawl cost (A5, A6).

## G. Multilingual
G1. hreflang: "If two pages don't both point to each other, the tags will be ignored."; each version lists itself; x-default for unmatched users; ISO 639-1 + ISO 3166-1 Alpha 2 only ("Only language codes listed in ISO 639-1..."); three methods (HTML link, HTTP Link header, XML sitemap), equivalent. https://developers.google.com/search/docs/specialty/international/localized-versions
G2. Sitemaps can carry localized versions (details on the localization page).

## H. Myths / things that do not help (with sources)
H1. llms.txt, AI text files, special markup, chunking: Google says not needed (E1, E2). Keep only if other services want it.
H2. Special schema for AI Overviews: "no special schema.org markup" (C13).
H3. changefreq / priority in sitemaps: ignored by Google and Bing (A3, A9). Sitemap ping: dead (A4).
H4. FAQPage markup for rich results: feature removed May-June 2026 (C8).
H5. ItemList markup on category pages for carousels: Google supports only Course, Movie, Recipe, Restaurant (C9).
H6. Product rich results without offers/review/aggregateRating: not eligible; fake ratings or prices break C1 (C4).
H7. Blocking Google-Extended to "leave AI Overviews": does not do that (E3); nosnippet/noindex do, at cost of Search snippets (B5).
H8. Keyword stuffing: lowest GEO method, below baseline (E9). Meta descriptions as keyword lists: less likely to be shown (D2).
H9. Identical descriptions or boilerplate titles on every page (D1, D2).
H10. Blocking GPTBot hides you from ChatGPT search: no, search uses OAI-SearchBot (E4). Blocking IP ranges to stop crawlers: unreliable (E6).
